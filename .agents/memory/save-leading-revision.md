---
name: Save advances the IDE
description: Successful LUMP saves are explicit authority to advance the matching IDE working selection, not merely publish to a detached library.
---
Saving a new LUMP must realign the IDE to that exact saved revision: repository,
History, matching Namespace selection, and validated private simulation.

**Why:** The user explicitly rejected a successful save leaving History and
execution on obsolete artifacts: “the leading edge of progress instead of a
stale, outof date solution”. This supersedes the earlier artifact-only-save UI
policy for the IDE working selection.

**How to apply:** Preserve immutable history and unrelated assignments. Stop
stale execution before replacing a whole validated simulation; never splice
live code and c-lists or touch hardware. Failed downstream preparation must
not roll back a successful artifact save or masquerade as current execution.
New unassigned copies need an explicit destination; unsupported design-profile
admission must remain blocked rather than borrowing a legacy image.
