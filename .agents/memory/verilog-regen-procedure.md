name: Verilog/RTLIL regeneration procedure
description: How to regenerate all build artifacts after an Amaranth source change; which files are actively-synthesised vs. legacy-frozen.
---

## Commands (run from workspace root)

```bash
python3 -m hardware.gen_verilog           # build/church_core.v  (ONLY church_core.v — no tang nano)
python3 -m hardware.gen_verilog --iot     # build/church_core_iot.v
python3 -m hardware.gen_verilog verilog   # verilog/church_core.v  (check-stale-cr7 target)
python3 -m hardware.gen_rtlil             # build/church_wukong_xc7a100t.il + .v
```

**IMPORTANT — known gaps vs. regen procedure:**
- `gen_verilog.py` only handles `--iot` flag; `--ti60` and all other `--` flags are silently ignored → it always calls `generate_core_verilog()`.
- `gen_verilog verilog` outputs only `verilog/church_core.v`, NOT `verilog/church_tang_nano_20k.v` (that file has no generator; leave at its last known-good state).
- `gen_rtlil.py` has no `--ti60` or `--wukong` flag logic in `__main__`; all flags are ignored and it always generates Wukong only.
- `build/church_ti60_f225.v` / `build/church_ti60_f225.il` are NOT generated by any gen_* command; they come from the OBBS pipeline (gen_verilog → Efinity synthesis).
- `build/church_tang_nano_20k.il` has no generator; it is effectively retired.

## Verification signal (ECO-001B)

Any freshly-generated file should have `drx_val_reg` and `eff_off` signals:
```bash
grep -c "drx_val_reg\|eff_off" build/church_core.v   # expect 16+
```

## CR6 perm fix verification (ECO-CR6-L)

After regeneration, verify `cr6_adjusted[30:28] = 3'h1` (L-permission constant):
```bash
grep "cr6_adjusted\[30:28\]" build/church_core.v verilog/church_core.v
```
Both lines must read `= 3'h1;` (hex 1 = binary 001 = L). If it reads `= 3'h4;` (= 100 = E), the perm.eq(0b001) in hardware/call.py has not propagated.

## Legacy-frozen (no gen script; reference church_machine/ legacy module)

- build/church_top.v
- build/church_pico_ice.v
- build/church_tang_nano_9k.v / .il

**Why:** These reference `church_machine/top.py` and `church_machine/pico_ice.py` — a legacy tree. No gen_verilog/gen_rtlil target exists for them; leave as-is.

## Builder tab visibility trap

`#builderViewTab-lump-resident` (and lump-thread, lump-ns) ship with `style="display:none;"` in index.html. `switchBuilderViewTab()` shows/hides the PANEL div, but never touches the tab BUTTON visibility. If the button is hidden, e2e tests that `waitFor({state:'visible'})` on it will time out (40 s each). Fix: remove the inline style from the button in index.html.
