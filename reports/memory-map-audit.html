Memory-map audit — simulator, IDE, ISA review and LUMP bytes

Date: 2026-10-10. Read-only audit; no migration or release approval.

Conclusion

The current committed image has a coherent, measurable current-format map. It is not an implementation of the red-text Namespace redesign. A single bit-correct new map cannot yet be declared: address-unit normalization, metadata/slot-role changes and the latest kind encoding need explicit agreement. The user's current requirement is W3 remains T, the IDE LUMP identifier. The latest W0-low-bit kind scheme is a proposal, not an adopted encoding.

This audit does not validate synthesized initialization, execute the boot path, check a physical board or establish that execution passes address 0x2E08. The earlier synthesized-initializer investigation remains incomplete.

Evidence and reproducibility

  • Committed image: server/lumps/boot-image.bin, 65,536 bytes / 16,384 words.
  • SHA-256: 0ff1b24d76b7010c13b8b50737f4513a771b586be73b8d0fa80a748087070a5b.

3. Conflicts that block a single new bit-correct map

A. Critical: proposed address tags cannot be applied to current word locations

The proposed W0 low-bit kinds depend on a word-aligned byte base. Current RAM W0 is a word location. For example Boot.Thread raw W0=0x10 means byte offset 0x40 here. Treating it as byte address 0x10 silently moves the target. Other valid word locations may have nonzero low bits.

Decision needed: an explicit new byte-addressed resident profile and conversion at every boundary. Validate base alignment before OR-ing a tag; never round an unaligned input down. Mask the tag before address arithmetic, but include the tagged W0 in integrity. Nonresident representations need separate handling.

B. Critical: the review's slot roles are not the current slot roles

Current code/image: 16-word NSH2 header at bottom; slot 0 self, slot 1 Thread, slot 2 UART. Review: metadata at slot 0, self at slot 1, initial Thread at slot 2, and no separate 16-word header.

Both use descending four-word slots, but their contents are incompatible. Migration needs rebuilt slot bindings, GTs, localized C-lists and Thread homes; relabeling UI rows or moving a header is insufficient. The selected bytes must remain immutable until an explicitly approved replacement image exists. Sources: shared/namespace_header.py:1–23, current image, review “Namespace metadata and fixed slots”.

C. Critical: saved red-text review is stale relative to the conversation

reports/isa-seven-items-review-proposals.md still assigns kind to W3, proposes an extra rotated-W3 integrity term and reuses resolved cache-token storage for kind. The user's later requirement explicitly retains W3 as T.

Those W3-kind passages are superseded design material, not the latest authority. The subsequent W0 tag proposal has not been approved or encoded in the review. This audit does not silently approve it or rewrite that history. Keep a single active decision table before building a new image.

D. High: new I/O arrival records are not supported by existing decoders

The general simulator header decoder still interprets cc/count/size using existing LUMP fields; it has no two-word simple-I/O/framebuffer branch. Its valid flag primarily checks marker bits; specialized consumers perform further checks. Proposed subtype records must not be passed as ordinary RAM-backed LUMPs merely because their marker is valid.

Current MMIO entries have numeric descriptors, not evidence of the proposed two-word definition stream. Sizes, subtype and exact transfer length require matched IDE emitter, server validator, simulator decoder and hardware support.

E. High: IDE and simulator currently agree on the old interpretation

The IDE displays raw location, exact W1 limit, integrity and T; current save/restore paths preserve that ABI. app-memory.js:2839–2868 explicitly uses the canonical W1 parser and W3 cache token. parse_ns_table_raw() returns the committed image's raw words rather than synthesizing them from UI fields. This consistency is useful, but is not conformance to the new review.

The current image proves why T must be retained. The same resident LUMP's manifest/pinned token can differ from its bootstrap GT-shaped descriptor T. For example WukongCallHome's selected saved token is 313e637c, while raw slot W3 is 4a000007. Do not treat every field named “token” as the same namespace or strip one identity merely because bootstrap sometimes equates them.

Static path audit does not establish that an open browser's unsaved design, loaded simulator state and committed image are identical. The report's exact map is the committed image above, not a claim about every IDE view at runtime.

F. High: master authority must be read with its correction preface

The master contains 32 repeated “Church Machine Instruction Set” titles and historical instruction sections. Its opening authority section explicitly prioritizes current corrections and rejects retired fused instructions. Repeated historical CR13/recovery and fused-opcode descriptions must not be used to override that preface or the review's separately agreed direction. Neither a broad text search nor a late occurrence alone is a normative spec.

G. Catalog finding requiring separate investigation

92 distinct manifest-referenced LUMP files have valid header magic and their file word counts match both the independent decoder and the current simulator header decoder. The IDE structural checker reports:

  • One file with errors: SlideRule.Haskell.1.3542a2db.lump.
  • RCI: branches at instruction positions 126, 131 and 133 target 141, 144 and 147, beyond the checker's code range 0…136.
  • Eight files have warnings; full messages are retained in the JSON.
  • A PostFlashSelftest manifest record has no filename. This is incomplete catalog evidence, not proof that a particular file was deleted.

The jump report is a checker finding, not a confirmed runtime diagnosis; no automatic repair was attempted. That file is not one of the three executable residents compared above. No claim that all catalog LUMPs are release-ready.

4. Candidate new map specification — pending approval

Keep identities and authority separate: GT for access, T for IDE LUMP identity, both retaining their full current widths. Do not require permanent T=GT.

For a new byte-addressed Namespace with base B, capacity C words and N slots:

slot(s).byte_address = B + 4*C - 16*(s+1)
table.byte_range    = [B + 4*(C-4*N), B + 4*C)
RAM.byte_range      = [B, B + 4*C)

Require alignment, nonwrapping arithmetic, N>=3 and enough room for table and the explicit prepared resident allocations. No blanket 64-slot assumption.

Slot Proposed review role
0 Metadata: W0 Namespace header, W1 B, W2 following-member count M, W3 reserved zero
1 Namespace self-entry
2 Initial Thread
Others Explicit prepared bindings, not inferred from arrival order

For resident entries, the latest unapproved proposal is:

W0 = aligned_base_byte_address OR kind
kind = 0 ordinary, 1 simple I/O, 2 framebuffer; 3 invalid
W1 ordinary/simple = existing limit[20:0], sequence[29:21], G[30], F[31]
W1 framebuffer     = n[4:0], zero[20:5], sequence[29:21], G[30], F[31]
W2 = existing integrity32(tagged W0, W1)
W3 = T

GT permissions and generation checks remain unchanged. Code/C-list/Heap views retain exact bounds. Framebuffer word offsets must be below 2^n, with n=0…30 and whole-access/byte-address overflow checks. Save/restore must carry kind without misusing T. No new term involving W3 is needed merely to bind kind.

For this snapshot's C=16384, N=64, B=0, slot 0 would still begin at byte 0xFFF0, but would contain metadata rather than today's self-entry. Its header would be 0xF8810100. M cannot be taken blindly from occupied-slot count: the agreed arriving-member and recursive-stream rules must define it.

The ISA words and their serialization should be specified independently: retain explicit BE portable-LUMP and LE current-image boundaries unless a separate migration changes them. Do not call the two formats interchangeable.

5. Ordered steps to obtain an implementation-ready map

  1. Reconcile the review: retain W3=T; decide the W0 tag proposal and remove superseded W3-kind formulas from the active edition.
  2. Freeze one byte-addressed profile, including MMIO and overflow rules.
  3. Define T population/lookup for every new local entry and nonresident cases.
  4. Define member-to-slot and nested-stream rules; resolve the current UART slot-2 conflict with the proposed initial-Thread slot.
  5. Build an isolated candidate from exact pinned artifact hashes. Check physical allocation, exact view limits, embedded content, C-list relocation, boot target, Thread homes and all integrity words together.
  6. Require IDE/server/simulator decoders to agree on every emitted word. Exercise boundaries and tag/permission/generation failures before hardware.
  7. Only then seek separately authorized synthesized execution evidence.

No live catalog rewriting, boot regeneration, routing, image programming, physical-board command or task-completion claim accompanies this audit.
