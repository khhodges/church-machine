# SELF relocation contract

SELF names the owner capability; it is not a separate architectural token type.
Before a destination exists, newly compiled C-list row zero is the architectural
NULL word, `0x00000000`. Its integrity-covered relocation declaration identifies
row zero as compiler-owned SELF with exactly E rights. NULL carries no authority
and does not predict a slot or generation. This uses the existing unresolved
C-list relocation rule, not a new marker.

Binding on a private copy replaces that row with an Inform, Church-domain,
E-only GT, B=0, using the exact selected owner slot and generation. Saved bytes,
hashes and signatures remain unchanged. Rebinding starts from those original
bytes, never from a previous derivative. Unresolved external rows remain inert
and fault only when used.

Historical `0xFEED5E1F` bytes remain readable and eligible only through existing
authenticated relocation/installation evidence. They are decoded as Abstract
bits and labelled a legacy encoding discrepancy, not an architectural SELF
sentinel. Their acceptance does not authorize new producers to emit them.
Historical local SELF words require exact destination or proven source identity.
Changing saved artifacts requires explicit corrected-revision adoption.

IDX1 reload verifies its exact saved execution envelope and compiler source
before accepting embedded NULL SELF E. Historical concrete SELF must still be
well-formed E-only Inform with B=0. Ascending migration accepts NULL only with
the frozen artifact's matching authenticated compiler record and embedded
SELF E declaration; a hash-only review is not compiler authentication.
