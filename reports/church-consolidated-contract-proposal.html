Consolidated Church-Machine architecture and binary contract

Status: proposal for approval, not an implementation authorization. Prepared 2026-10-10. Historical master/review documents and retained images remain unchanged. Acceptance criteria below are requirements, not reported passes.

Purpose and authority

Consolidate one capability-constrained execution architecture and one explicit binary representation, then establish simulator and FPGA conformance separately. Do not claim universal termination or flawless physical operation from simulation. Finite-resource failure must be defined and authority-preserving.

The normative architecture specifies observable state, encodings, effects and faults. A separate binary contract specifies layouts and serialization. Implementation documents describe pipelines and verification machinery; they must not silently create architectural requirements.

Architectural execution contract

An abstraction comprises code and its capability environment. CALL validates entry authority, establishes the callee's environment and preserves the architectural continuation. RETURN restores the specified caller environment and validates its authority. LAMBDA executes in its specified scope and must not be silently given CALL's environment-switching behavior.

A capability is an authority-bearing reference, not simply a lambda variable; CALL is not by itself a proof of beta-reduction correctness. Before freezing compiler conformance, specify an executable calculus model, argument/result ABI, evaluation strategy, closure representation and recursion/resource behavior. These are semantic specification deliverables, not permission to invent new register roles. Pure programs must match that model; effectful programs must also match authorized effect sequences and faults.

CHANGE suspends/resumes exactly the canonical Thread state. Invalid encodings fault before condition evaluation as already agreed. Recovery must not depend on unapproved IRQ roles or newly invented architectural readiness registers.

Binary contract candidate

GT and identity

Keep the existing 32-bit GT and its type-specific encodings unchanged. Do not interpret Abstract-GT payload fields using the Inform/Outform layout. T never grants access. Content verification uses the full pinned identity/hash contract; a short T is not a collision-resistant replacement for that evidence.

Namespace geometry

For aligned byte base B, capacity C words and N slots:

RAM:   [B, B + 4*C)
table: [B + 4*(C - 4*N), B + 4*C)
slot(s): B + 4*C - 16*(s+1),  0 <= s < N

Use widened arithmetic for end calculations; reject overflow, overlap, unsupported capacity and N<3. Zero is a valid base. Slot 0 is metadata, never a capability-resolvable target:

Metadata word Meaning
W0 Namespace header
W1 Base byte address B
W2 Direct following-member count M
W3 Reserved zero; no new cold-boot seal

The existing common header positions remain: marker[31:27], size[26:23], count[22:10], type[9:8], cc[7:0]. Abstraction/Thread allocation is 2^(size+6) words; Namespace capacity is 2^(size+13) words. Count means code words, private-stack words or plain slot count respectively. Reserved values and unsupported sizes are rejected.

Namespace capacity, table slot limit N-1 and accessible data-view extent are distinct. Open encoding gate: define the exact Namespace self-view rule, including capacities beyond a 21-bit exact limit. Do not silently use N-1 as a RAM word bound, truncate capacity or infer wider authority from a header. This gate prevents declaring the candidate implementation-ready.

Resident capability entries

W0 = aligned_base_byte | kind
kind: 0 ordinary, 1 simple I/O, 2 framebuffer, 3 invalid
W1 ordinary/simple: limit[20:0], generation[29:21], G[30], F[31]
W1 framebuffer: n[4:0], zero[20:5], generation[29:21], G[30], F[31]
W2 = ROL32(W0,7) XOR ROL32(W1 & 0x3fffffff,13) XOR 0xdeadbeef
W3 = T

Check integrity on raw tagged W0; remove tags only for address arithmetic. Integrity is unkeyed consistency evidence. Existing authentication, authorized publication and GT checks are not replaced. G/F protection remains subject to existing authorized state transitions, not this checksum.

Kind and exact bounds survive all protected copies, continuations, Thread transitions and M-window operations without repurposing T storage. Open encoding gate: enumerate and freeze their exact context representation. Nonresident entries require their own explicit representation; no inference from low address bits or small token values.

I/O definitions

Two words arrive, with no executable body or C-list:

simple header = 0xf8000000 | (S << 10) | 0x300 | (W << 1) | R
frame header  = 0xf8000000 | (n << 22) | 0x304 | (W << 1) | R
second word   = aligned device byte base

S=1..8191; n=0..30; R/W are single bits, at least one set. All subtype-reserved bits are zero. Simple limit=S-1; framebuffer extent=2^n words. Full ranges and every multiword access must fit without wraparound. Mapping a definition performs no device access. It cannot grant execute, capability-transfer, DMA or GPU-control authority.

Type 11 replaces the historical Outform header in this new format; GT type encoding remains unchanged. This is an explicit cutover, not dual decoding.

Thread, boot and member binding

Preserve the canonical size-derived Thread layout: header +0, DR homes +1..16, protected indicator +17, Heap from +18, private stack before the final twelve capability homes. Preserve the poison-root frame and canonical continuation semantics. Resolve hardware lambda-return deviations before conformance.

Prepared initial Thread authority selects the boot entry. Import/Run must not silently repair it from the current editor or latest catalog.

Recommended loader framing: one prepared root context supplies extent and expected root identity; each Namespace consumes exactly M direct children, recursively. A prepared, authorized association supplies each child's slot, identity/hash and placement. Validate the complete graph before publication; reject missing/duplicate/extra members and cycles in containment. Do not assume code-call graphs are acyclic. No implicit permission widening on rebinding.

The exact transported association/framing representation remains a freeze gate; do not invent an on-wire extension by using an implementation manifest.

Tests must specify bounded execution and distinguish expected nontermination, resource exhaustion, tool timeout and actual pass. Finite testing is not a universal proof. Formal safety assertions should supplement instruction cases: no unauthorized effects, no out-of-range accepted accesses, no commit from an invalid continuation, and no lost/extra initialization write under the stated sink and clock assumptions.

Freeze gates and implementation sequence

Approval can accept direction without pretending the open encodings are solved. Before implementation, close: Namespace self-view extent, protected kind/context packing, nonresident representation, transported member association/framing, and calculus evaluation/ABI details. Publish complete bit vectors for each.

Then: simulator + binary contract first; compiler/IDE integration; isolated candidate preparation; RTL conformance; synthesized functional conformance. Only separately authorized later work may route, create/program a bitstream or command the board. Functional synthesis evidence does not establish timing closure.
